# Bang's-Edge — 開発・監査運用ルール

## 0. 位置づけ

本書は、discord-ai-hub MCP統合構想(`docs/concept-ai-hub-integration.md`、元はProject_Orbitalで作成)の実地検証として、このリポジトリで採用する**軽量な運用ルール**を定義する。Project_Orbitalの`docs/development-workflow.md`のような大規模なN1〜N40規範は本プロジェクトには存在しない。ここでは検証に必要な最小限のルールのみを定める。

## 1. データ共有方針

- **非公開(共有禁止)**: `docs/game-concept.md` に書かれた「アイデアの種」(ゲームの核となる発想・メカニクス・タイトル)。これをOpenAIのデータ共有モデル(discord-ai-hub経由の`gpt-5.6-*`系列)に送らない。
- **共有可**: 上記以外——実装コード、一般的な技術相談、定型作業、ドキュメント整備など。
- 適用範囲は`ask`/`compare`いずれも同様。`compare`の`models`配列に`gpt-5.6-*`を含める場合は、送信するプロンプトが`docs/game-concept.md`の内容(引用・要約・言い換え含む)を含んでいないか、都度確認する。

## 2. モデル別の役割分担(構想メモ§3.1を本プロジェクト向けに簡略化)

| 用途 | 使用先 | 備考 |
|---|---|---|
| 通常の実装(HTML/CSS/JS) | Claude Code | メイン担当 |
| 実装後の監査 | agyへのヘッドレス呼び出し(`--add-dir`、カスタムエージェント不使用) | §3参照。ファイル常設のカスタムエージェントは作らない方針(2026-09-10、ユーザー判断) |
| 行き詰まった一点だけ別視点が欲しい(非公開情報を含まない) | discord-ai-hub経由 `xai/grok-4.6` | 月$10共有枠(Vertex AI)を消費するため、設計書一式のような大きな投げ方はしない。1つの疑問に絞る |
| データ共有前提で問題ないコード生成・下書き | discord-ai-hub経由 `gpt-5.6-terra/luna`優先 | 日次無料枠あり。`docs/game-concept.md`の内容を含めない |
| 軽い壁打ち・生成 | discord-ai-hub経由 ローカルモデル(`google/gemma-4-12b-qat`等) | 常時無料 |
| ローカルモデルとGrokの比較 | discord-ai-hub `compare` | `models`配列に`gpt-5.6-*`を含めない(非公開情報を扱う場合) |

## 3. 実装 → 監査フロー(カスタムエージェント不使用・プロンプト側で縛る方式)

**方針(2026-09-10確定)**: `.agents/agents/<name>/agent.md`のような常設のカスタムエージェント定義ファイルは作らない。理由は、agyのカスタムエージェント検出には`--new-project --agent <name>`が必要で、`--new-project`を使うたびにAntigravity側のプロジェクト一覧が肥大化する(構想メモ§1.2既知の問題)ため。代わりに、監査の役割・観点を**プロンプト文字列側に埋め込み**、`--add-dir`でカレントディレクトリをワークスペースとして渡すことで、`--new-project`・`--agent`のどちらも使わずに監査を実行する。

**実証済み(2026-09-10、agy 1.1.28)**:
- `agy --model <model> -p "<prompt>"`(`--new-project`も`--agent`も無し)は、Antigravityのプロジェクト状態ファイル(`~/.gemini/antigravity/antigravity_state.pbtxt`)を変更せず、プロジェクト一覧を汚染しない。
- ただしこの形ではカレントディレクトリのファイルを読めない(ワークスペース未指定のため)。
- `--add-dir "<カレントディレクトリの絶対パス>"`を追加すると、指定ディレクトリ内のファイルを読めるようになり、かつ状態ファイルは変更されない(プロジェクト一覧を汚染しない)。

**監査プロンプトテンプレート**(呼び出し時に`<>`部分を埋めて`-p`に渡す):

```
あなたはWebゲーム「Bang's-Edge」のコード監査役です。以下の観点でレビューしてください:
1. docs/game-concept.md の仕様との整合性(操作方法・スコアリング・ラウンド構造)
2. コード品質(不要な複雑化・デッドコード・命名の明確さ)
3. パフォーマンス(Canvas描画、パーティクル数増加時のフレームレート低下の可能性)
4. GitHub Pages上の静的サイトとして動作する上での依存関係の問題

指摘は具体的なファイル名・行番号を挙げ、重大度(必須修正/推奨/任意)を付けて列挙してください。

監査対象: <対象ファイルや差分の説明>
```

**呼び出し例**:
```
agy --model gemini-3.8-flash-high --add-dir "C:\Users\ryoga\Documents\Bang's-Edge" -p "<上記テンプレートを埋めたプロンプト>"
```

モデルは呼び出しごとに選択する(固定しない)。素早い一次チェックは`gemini-3.8-flash-high`等、深い検討が必要な場合は`claude-opus-4-6-thinking`等を使う想定。

**フロー**:
1. Claude Codeが機能単位で実装する。
2. 上記テンプレートを埋めたプロンプトで`agy --add-dir ... -p "..."`を実行する。
3. 指摘があれば修正し、収束するまで2に戻る。
4. 何往復で収束したかを観察し、`docs/concept-ai-hub-integration.md` §1.2/§4に知見を追記する。

## 4. コスト報告

- discord-ai-hub経由でVertex AI(`xai/grok-4.6`)を呼ぶたびに`docs/cost-log.md`へ記録する。
- 月$10予算に対する消費ペースを把握するため、記録は都度・後回しにしない。

## 5. 検証後に持ち帰る情報(構想メモ§6.1に対応)

- `compare`除外ルールの運用可否 → 除外漏れが実際に起きたか、チェックリスト化が必要かを記録。
- agyとの往復フローの実用性 → 往復回数・`--new-project`肥大化の実害有無。
- コスト実測 → `docs/cost-log.md`の記録から$10予算消費ペースを算出。

結果は`docs/concept-ai-hub-integration.md`の該当セクション(§4, §6.2)へフィードバックする。

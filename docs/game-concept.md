# Bang's-Edge — ゲームコンセプト

> **⚠️ データ共有制限(2026-09-10に範囲を緩和)**
>
> 本プロジェクトは実験目的のため、**「明らかにユーザーのアイデアと分かるもの」以外は共有可**とする(ユーザー判断)。
>
> - **非公開(`gpt-5.6-*`に送らない)**: 下記の「概要」「ゲームメカニクス」「スコアリング」「ラウンド構造」——すなわち*赤い粒子をマウスの長押しで集め、ビッグバンが起きる直前に離して密度を競う*という発想の組み合わせと、タイトル`Bang's-Edge`。
> - **共有可**: 下記の「実装仕様」(密度の数式・各パラメータ・音響設計)、実装コード、一般的な技術相談、定型作業。これらは物理計算や音響合成の技術的問題として抽象化でき、ゲーム固有の発想を明かさずに相談できる。
>
> 判断に迷う場合は、そのプロンプトだけ読んで「どんなゲームか」が復元できてしまうかを基準にする。復元できるなら`gpt-5.6-*`を`models`配列から外す。ローカルモデル・Vertex AI(`xai/grok-4.6`等、月$10共有枠に注意)・agy経由のモデルには、本ファイル全体を渡してよい。

## 概要

- プラットフォーム: Web(ブラウザ上で動作)。最終的に GitHub Pages で公開。
- 操作: マウスのみ(クリック/長押し/ドラッグ)。キーボード操作なし。
- タイトル: **Bang's-Edge**

## ゲームメカニクス

1. 画面上に赤い粒子(パーティクル)が存在する。
2. プレイヤーが画面内の任意の位置でマウスボタンを押し、押し続けながらカーソルを動かすと、周囲の粒子がカーソルに引き寄せられる。
3. クリックを押し続けている時間が長いほど、粒子を引き寄せる**集積範囲**と**引き寄せる強さ**が上昇していく。
4. 集積が進みすぎると **ビッグバン** が発生し、その回は失敗(アウト)となる。
5. プレイヤーの目的は、ビッグバンが起きる**ギリギリの直前でマウスボタンを離す**こと(離す = 収集を止めて確定させる操作)。
6. マウスボタンを一度離したら、その時点でラウンド終了。スコアが確定し、リスタート待ち状態になる。

> 補足: 元指示文中の「話す」は「離す」(マウスボタンを離す)の誤字と解釈して上記に反映した。異なる場合は要修正。

## スコアリング

- スコアは**粒子密度**をベースに算出する(密度が高いほど高スコア)。
- ゲーム全体の目的は、ビッグバンを起こさずに**到達できる最高密度**を追求すること。
- ビッグバンが発生した場合は失敗(そのラウンドのスコアは0。下記「実装仕様」参照)。

## ラウンド構造

- 1プレイ = 1回のクリック開始〜1回のリリース(離す)まで。
- リリース後はその場でラウンド終了 → リスタート。
- 「離す」までの間に複数回クリックし直せるか(=中断してやり直せるか)は未確定。現状の記述では「一回離したら終了」のみが明言されている。

## 実装仕様(2026-09-10確定)

agyへ委任した設計提案をBrain(Claude Code)が検証し、致命的欠陥2点を修正して確定したもの。パラメータは`config.js`に定数として外出しし、プレイテストで調整する前提。

### 密度の計算

**カーソル中心の固定測定円**(半径`R_MEASURE`)の内部にある粒子数で測る。集積半径`r(t)`とは切り離す。

```
density    = N_measure / (π × R_MEASURE²)
DENSITY_MAX = TOTAL_PARTICLES / (π × R_MEASURE²)
dangerRatio = density / BANG_THRESHOLD
score      = floor(density / DENSITY_MAX × 9999)
```

> **なぜ集積半径で割らないか(重要)**: 当初案は`集積円内の粒子数 ÷ 集積円の面積(πr²)`だったが、`r`が時間で30→280pxに広がるため分母が最大87倍に膨張し、全粒子を集めても理論最大の約1.1%にしかならず、しきい値85%に**原理的に到達不可能**だった(ビッグバンが永久に起きない)。分母を固定することで「測定円にどれだけ詰め込めたか」が素直に密度になり、長押しで引力が強まる→中心に集まる→密度上昇→危険、というチキンレースが成立する。

### 粒子の運動

各粒子に毎フレーム、カーソル方向への加速度と**速度減衰**を適用する。

```
dir  = normalize(cursorPos - particlePos)
vel += dir × F(t) × dt
vel *= DAMPING          // ← 必須
pos += vel × dt
```

> **なぜ減衰が必須か(重要)**: 減衰なしだと粒子はカーソルを通過して反対側へ行き、単振動するだけで集積しない。`DAMPING`が粒子をカーソル周辺に収束させる。

画面端では反射させ、粒子が画面外へ消失しないようにする。引力圏外の粒子には微弱なランダム揺動を加える。

### 時間変化(押下からの経過時間 t 秒)

指数飽和曲線で、集積半径と引力を上昇させる。

```
r(t) = R_MIN + (R_MAX - R_MIN) × (1 - e^(-t / TAU_R))
F(t) = F_MIN + (F_MAX - F_MIN) × (1 - e^(-t / TAU_F))
```

`TAU_F < TAU_R`とし、引力を半径より先に立ち上げる。これにより「範囲はまだ狭いのに中心の密度だけ急上昇する」局面が生まれ、単純な時間管理では最適解に辿り着けなくなる。

> **なぜ集積半径の上限を画面相対にするか(重要)**: 当初は固定280pxだったが、1920x1080画面では面積の約12%しかカバーせず、引力圏に入る粒子が約24個しかないため、しきい値の170個に**原理的に到達できなかった**(数値シミュレーションで20秒押し続けても危険度13.5%で頭打ちを確認)。画面対角線の0.55倍とすることで全粒子が射程に入り、危険度が「4秒:17% → 6秒:56% → 8秒:88% → 9.3秒で発火」と推移する。7〜9秒あたりで「離すか粘るか」を迫られる狙い通りのカーブになる。固定pxではなく比率にすることで、ウィンドウサイズが変わっても体験が保たれる。

### 粒子間反発と引力中心の揺動(2026-09-10追加)

初版の実装には**空間的な構造が全く無かった**。引力の大きさが距離によらず一定で粒子同士に相互作用が無いため、集まった粒子は文字どおり1点に重なる(t=9秒時点で測定円内160個の最近傍距離が中央値0.00px、カーソルからの距離は90パーセンタイルで0.5px)。その結果、密度は単調に増えるだけで、爆発時刻の試行間ばらつきは標準偏差0.23秒しかなく、**「9.2秒で離す」と覚えれば解けるストップウォッチ**になっていた。さらにカーソルを中央から外すと到達が24秒以上に伸びるため、「中央に置いて動かさない」が唯一の最適戦略で、マウス移動という入力の自由度が死んでいた。

これを解くために3つを同時に導入する。3つは互いに依存しており、どれか1つを外すと成立しない。

**1. 粒子間反発(有限レンジ線形)**

```
d < REPULSION_D0 のペアにのみ作用
f(d) = REPULSION_K × (1 - max(d, REPULSION_EPS) / REPULSION_D0)
```

塊に実際の広がり(半径およそ48px)を与える。1/d² や Lennard-Jones ではなく有限レンジ線形を使うのは、d→0 で発散せず力の上限が `REPULSION_K` に留まり、明示的オイラー法で安定だから。粒子が完全に重なった場合は方向が定義できないので、**添字のハッシュから決まる固定方向**へ押し分ける。

> **ここで`Math.random()`を使わないこと(重要)**: 毎フレーム方向が変わると系が加熱して破綻する。方向は添字から決定論的に決める。

**2. 引力中心の微小揺動**

```
attractX = cursorX + WOBBLE_AX × cos(2π × WOBBLE_F1 × t)
attractY = cursorY + WOBBLE_AY × sin(2π × WOBBLE_F2 × t)
```

**引力はこの揺動した点を中心に働くが、密度の測定円は生のカーソル位置を中心に据え置く。** これにより塊の芯がカーソルから少しずつ外れ続け、測定円を芯へ当て直す操作(カーソルの微調整)が意味を持つ。乱数ではなく非整数比の2周波なので、周期が目立たず、かつ上達可能な動きになる。

> **なぜ振幅を大きく取るか(重要)**: 揺動2pxでは追従操作の利得が密度+2%しかなく、体感できない。12pxで+26%になる。塊の半径が約48pxあるため、振幅がそれに対して十分な割合でないと芯が測定円から出ない。

**3. 減衰の緩和(`DAMPING` 0.92 → 0.975)**

上の2つを入れても、**減衰0.92のままでは追従の利得が+3%に潰れる**。減衰が強すぎると粒子が揺動する中心に瞬時に追いつき、塊が遅れないため。0.92は時定数0.20秒に相当し緩和が速すぎる。0.975(時定数0.83秒)にすると塊が遅れて歪み、追従が効くようになる。

**4. 引力の際限ない上昇(`F_CREEP`)**

```
F(t) = F_MIN + (F_MAX - F_MIN) × (1 - e^(-t / TAU_F)) + F_CREEP × t
```

> **なぜ必要か(重要)**: 上の1〜3だけだと、反発と引力が釣り合う平衡個数が発火しきい値の170個に届かず、**押し続けても永久に爆発しない**(12試行すべてで40秒間発火せず)。これはビッグバンが起きなければゲームが成立しないという初版と同じ欠陥である。飽和しない項を1つ足して、いずれ引力が反発を押し切るようにする。

**結果として成立する遊び**

| 遊び方 | 爆発時刻 | t=7秒時点の密度 |
|---|---|---|
| カーソルを動かさない | 約21秒(SD 1.3秒) | 基準 |
| 塊の芯を追いかける | **約7.7秒**(SD 0.8秒) | **+18〜26%** |

放置は安全だが低スコアで頭打ち、攻めれば高密度に届くが爆発圏に入る。**リスクが「時間の経過」ではなく「どこまで攻めるか」という選択になる。** 試行間のばらつきも0.23秒→0.8〜1.3秒に拡大し、ストップウォッチでは解けなくなった。

副次的に**画面サイズ依存も解消された**。1280x800〜3840x2160 の範囲で静止時の爆発時刻が21.0〜22.3秒に収まる(導入前は7.5〜9.6秒と21%ぶれていた)。反発が絶対pxで詰まり方を決めるため、初期配置の粗密の影響が小さくなる。

**計算コスト**: 200粒子の総当たり19,900ペアで、最密状態の`update()`が1回0.106ms(60fpsの予算16.7ms)。空間分割は不要。

### 初期配置のクラスタ化(2026-09-10追加)

一様ランダムだと200個の平均化でラウンド間の差が消える。`SPAWN_UNIFORM_FRAC`の割合だけ従来どおり一様に撒き、残りを`SPAWN_CLUSTERS`個のクラスタへ均等に振り分け、各クラスタ中心から標準偏差`SPAWN_SIGMA`の2次元正規分布で配置する(画面内にクランプ)。クラスタ中心は毎ラウンド一様ランダムに取り直す。

これ単体でも爆発時刻の標準偏差が0.25秒→0.79秒と3倍以上になる。序盤は集積半径が30pxと狭いため、どの塊を先に拾いに行くかというルート取りが生まれる。

### ビッグバン

`density >= BANG_THRESHOLD`の状態が`BANG_GRACE_FRAMES`連続したら発生。猶予フレームにより「一瞬触れたがセーフ」という体験が成立する。**発生時のラウンドスコアは0**(中途半端な保持を認めるとチキンレースの緊張感が消えるため)。ハイスコアは別途保持するのでそれ自体は消えない。

### 危険度フィードバック

`dangerRatio`に応じて4段階(SAFE / WARM / HOT / CRITICAL)で、粒子の色(白→黄→赤→白熱)・集積円の太さと色・画面振動・上部の密度バーを連動させる。複数チャネルを重ねることで、画面のどこを見ていても危険を体感できるようにする。

### 音(2026-09-10にスコープへ追加)

**Web Audio APIによる合成音のみ**を使う(音声ファイルは持たない。外部アセットの調達もビルドも不要で、GitHub Pagesにそのまま乗るため)。

- **押下中の持続音(ドローン)**: 押した瞬間から鳴らす。危険度に関係なく常に聞こえることが重要(初版は危険度40%から鳴り始める設計で、体感では「5割を超えたあたりでようやく聞こえる」状態だった)。`dangerRatio`に応じて基音を130→300Hzへ、音量を0.04→0.18へ、ローパスを900→5000Hzへ上げ、緊張が高まるほど明るく刺々しくする。
  > **`sawtooth`波と低い基音を使わないこと(重要)**: 試作で基音55→110Hzのsawtoothを使ったところ、**バイクのエンジン音に聞こえる**という指摘を受けた。低周波のsawtooth+可変ローパスはエンジン音の合成レシピそのもので、緊張感ではなく走行音になってしまう。基音は`triangle`(倍音が少なく柔らかい)、重ねる倍音は完全5度上(1.5倍)の`sine`とし、音程帯も上げる。
- 危険度連動の警告パルス: ドローンに重ねる。`dangerRatio` 0.30から鳴り始め、上がるほど間隔が短く・音程が高くなる。視覚から目を離していても「そろそろ限界」が分かるようにする。
- **ビッグバン**: 「ドカーン」と感じられる迫力が要る(初版は650msで「パン」程度の軽さだった)。全体1.8秒の3層構成にする——アタック層(高域ノイズを5000→200Hzへ0.12秒で落とす立ち上がり)、ボディ層(サイン110→28Hzの下降、ディケイ1.4秒)、テイル層(ノイズを800→60Hzへ1.8秒かけて落とす余韻)。
  > **アタック層を強くしすぎないこと(重要)**: 3層版の試作でアタック層をgain 0.85・高域12000Hz始まりにしたところ、**「パンという音が強すぎる」**という指摘を受けた。一方でボディ層の「ドゥーン」は好評。爆発の主役は低域のボディであり、アタックはその立ち上がりを縁取る程度でよい。アタックはgain 0.20・5000Hz始まりに抑え、ボディを0.95、テイルを0.55として低域を前に出す。
- **リリース確定**: 軽い「ポ」ではなく、余韻のある確定音にする。完全5度の和音(440Hz+660Hz)を三角波で0.35秒、やわらかいアタックとゆるやかなディケイ。
- ミュート切り替えを画面上に置く(マウスのみ操作のため、キーボードショートカットには依存しない)。ミュートボタン上のクリックはラウンド開始として扱わない。

AudioContextはブラウザの自動再生ポリシーにより、ユーザー操作を伴わずには開始できない。本作は最初の押下が必ず操作なので、そこで`resume()`する。

### パラメータ初期値

| パラメータ | 初期値 | 用途 |
|---|---|---|
| `TOTAL_PARTICLES` | 200 | 粒子総数 |
| `MARGIN` | 20 px | 初期配置の画面端マージン |
| `R_MEASURE` | 40 px | 密度測定円の半径(固定) |
| `R_MIN` | 30 px | 集積半径の下限(押した瞬間) |
| `R_MAX_RATIO` | 0.55 | 集積半径の上限。**画面対角線に対する比率**(1920x1080で約1211px) |
| `TAU_R` | 3.0 s | 集積半径の時定数 |
| `F_MIN` / `F_MAX` | 50 / 800 px/s² | 引力 |
| `TAU_F` | 2.5 s | 引力の時定数(半径より短い) |
| `DAMPING` | 0.975 | 速度減衰(毎フレーム換算)。**0.92では追従操作の利得が消える** |
| `BANG_THRESHOLD` | `DENSITY_MAX × 0.85` | ビッグバン発生しきい値 |
| `BANG_GRACE_FRAMES` | 5 | 猶予フレーム(約83ms) |
| `DANGER_WARM/HOT/CRITICAL` | 0.40 / 0.70 / 0.90 | 危険度ゾーン境界 |
| `F_CREEP` | 30 px/s³ | 引力の際限ない上昇。これが無いと永久に爆発しない |
| `REPULSION_K` | 4000 px/s² | 粒子間反発の係数 |
| `REPULSION_D0` | 8 px | 粒子間反発の相互作用半径 |
| `REPULSION_EPS` | 0.05 px | 反発方向が定義できない最小距離 |
| `ACCEL_CLIP` | 8000 px/s² | 1粒子あたりの合成加速度の上限 |
| `VELOCITY_CLIP` | 720 px/s | 速度の上限 |
| `WOBBLE_AX` / `WOBBLE_AY` | 12 / 9 px | 引力中心の揺動振幅 |
| `WOBBLE_F1` / `WOBBLE_F2` | 0.73 / 0.97 Hz | 揺動周波数(非整数比) |
| `SPAWN_CLUSTERS` | 5 | 初期配置のクラスタ数 |
| `SPAWN_SIGMA` | 55 px | 各クラスタの標準偏差 |
| `SPAWN_UNIFORM_FRAC` | 0.35 | 一様に撒く粒子の割合 |

これらは実際に遊んで調整する前提。特に`TAU_R`・`TAU_F`・`BANG_THRESHOLD`・`DAMPING`がゲームフィールの核。

# discord-ai-hub 呼び出し手順書

## 1. 呼ぶ前(送信可否とモデル選択)
- [ ] 送信可否の判定: `gpt-5.6-*` に送る前に「このプロンプトだけでどんなゲームか復元できるか」を判定し、復元できるなら `gpt-5.6-*` を使わない。非公開範囲は `CLAUDE.md` の最優先制約が正本であり、本スキルより優先する。
- [ ] `compare` のモデル確認: `compare` を使う場合は `models` 配列に `gpt-5.6-*` が含まれていないかを送信前に確認する(サーバー側の自動除外なし)。非公開情報に近い相談は `ask` を個別に呼ぶ。`compare` はモデルを順番に処理するため、推論の遅いローカルモデルを含めると全体の時間が大きく延びる。
- [ ] 過去実績の確認: 委任前に `docs/model-experiment-log.md` を確認し、類似タスクの成否・effort実績を参考にする。
- [ ] モデル選択とコスト(最新一覧はMCPリソース `models://registry` を優先):
  - ローカルモデル(`google/gemma-4-12b-qat` 等): 常時無料。ローカルで足りるタスク(軽い壁打ち・生成)はまずこれ。
  - `gpt-5.6-terra` / `gpt-5.6-luna`: クラウドモデルが必要な場合の第一候補。日次無料枠が合算250万トークンと大きく、金銭コスト0。
  - `gpt-5.6-sol`: 深い設計向け(日次無料枠25万トークン)。受付判定で「当日使用量 + プロンプト×1.5 + 出力上限32,000」を見込むため、残りが約3万トークン+プロンプト分を切ると当日利用不可になる(集計自体は実使用量)。
  - `xai/grok-4.6` / `gemini-3.8-flash`: Vertex AI経由で月$10共有枠を消費するため、行き詰まった一点に絞って利用。`gemini-3.8-flash`は100万トークン超の長文脈が必要な場合に選ぶ。
- [ ] 出力上限と effort: `gpt-5.6-*` は出力上限32,000に推論トークンも含む。長い回答が要る質問は effort を上げず、最初から分割する。
- [ ] ローカルモデルの並行禁止: ローカルモデルへの要求は、別のローカルモデルと並行させない(LM Studio上で別モデルが要求されるとアンロードされて生成が打ち切られる実例あり)。

## 2. 呼び出し方
- [ ] 未使用引数の渡し方: Claude Code側のツール定義が古く全引数必須になっているため、使わない引数には本物の `null` を渡す(文字列の `"null"` ではない。特に `temperature` は文字列を拒否する)。
- [ ] `session_id` の指定: `ask` で短期履歴を使う場合はタスクごとに一意なIDを指定する(有効期限20分・最大20往復・プロセスメモリ上のみ)。単発なら `null`。なお `compare` は `session_id` 非対応。
- [ ] バックグラウンド移行の待機: `ask` が120秒を超えるとバックグラウンドタスクに移る。結果を推測で書かず、完了通知を待って確認する。

## 3. 呼んだ後(毎回確認)
- [ ] 途中切れの確認: `ask` の応答末尾に `[⚠` で始まる注記があれば出力上限による途中切れ。切れた見出しの中身を短い質問で取りに行く(特に安定性・限界・上限を扱う節)。
- [ ] `compare` の結果確認: `compare` では各モデル結果の `error` と `warning` を確認する(`warning` が `null` でなければ不完全な可能性あり)。
- [ ] 空応答時の再試行: 本文が空ならエラーで返る。effort を下げるか質問を分割して再試行する。
- [ ] コンテキスト超過エラー: 上限超過エラーが出た場合は、新しい `session_id` で仕切り直すか短いプロンプトで再試行する。
- [ ] 原因の断定禁止: 失敗の原因を1回のサンプルで断定しない。サーバー側の原因と推定する場合は、観測した事実と推定を分けて書く。

## 4. 記録(後回しにしない)
- [ ] 実験ログの追記: `docs/model-experiment-log.md` に1行追記する(列構成: `| 日付 | タスク内容/種別 | 委任先 | モデル | effort | 結果 | 選択理由 | 備考 |`)。
- [ ] コストログの追記: Vertex AI系(`xai/grok-4.6`、`gemini-3.8-flash`)を呼んだら、失敗やタイムアウトでも枠を消費した可能性があるため `docs/cost-log.md` に追記する(列構成: `| 日付 | ツール(ask/compare) | モデル | 目的 | 備考 |`)。
